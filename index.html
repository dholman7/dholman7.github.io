Six projects that build, test, and measure AI coding agents

Each project is public, runs on its own, and backs one claim from the resume with something you can run and check. Together they form one loop: an agent turns a Jira story into a verified Playwright test, a reviewer checks the pull request, and a benchmark measures whether any of it works.

What's in this portfolio

Six projects, each in its own public repository. Click a name to jump to what it does and how to run it.

  • Storywright is an AI agent that writes and verifies automated tests from a Jira story, then opens the pull request.
  • review-loop is an AI code reviewer for pull requests that double-checks every comment before posting it.
  • agent-eval-gate is a benchmark that measures how well test-writing agents work, using deliberately planted bugs.
  • agent-telemetry is a live dashboard of those measurements, down to each individual run.
  • ci-context-mcp lets AI coding assistants read build results and logs, so they can answer "why did CI fail?"
  • vendor-intake-app is a working web app (Next.js + Python) that all of the above test against.

App under test

vendor-intake-app

A small but real vendor-onboarding product: members upload a W-9, insurance certificate, and contract; the app extracts fields; reviewers approve or reject. Every agent in the portfolio writes tests against it.

Proves
React + TypeScript and Python in one product, specified in Gherkin, with an LLM feature tested like any other
Stack
Next.js 16, React 19, FastAPI, SQLAlchemy, SQLite, Playwright, Docker
Evidence
92 backend tests (96% coverage), 31 Playwright tests with accessibility scans, 42 Gherkin scenarios. Optional Claude extraction, with every value grounded in the document's own text: 99% field accuracy on held-out documents from a 75-document generated set, and 0 wrong values at high confidence.
Repository
Run it with Docker 
cd vendor-intake-app
make up    # web on :3000, API docs on :8000/docs
Or without Docker (uv and Node 24) 
make install && npm ci --prefix frontend
make dev   # seeds demo data
make check # backend lint, types, tests

Sign in as member@northwind.test or reviewer@northwind.test, password demo-password.

Measurement

agent-eval-gate

A benchmark and CI gate for agents that write tests. Each of its 42 tasks (32 API, 10 UI) is one Gherkin scenario. A generated test counts only if it passes on the real app and fails when a hand-written bug is seeded in.

Proves
Agent evaluation that holds up: frozen dev/held-out split, confidence intervals, record and replay
Stack
Python, Playwright, OpenTelemetry, GitHub Actions composite action
Evidence
Every seeded bug is proven catchable by a reference test. The gate pairs runs task by task and fails a PR only on a drop that is both significant and at least 5 points. At 20 tasks × 3 trials it catches a 20-point drop 87% of the time (interval overlap: 47%), and the README says what it can't see.
Repository
Run it (uv; no API key) 
cd agent-eval-gate && uv sync
uv run aeg validate        # references pass, every bug caught (~2.5 min)
uv run aeg run --agent reference --split dev
uv run aeg gate --baseline baselines/reference-dev.json --current results/latest.json
Score your own agent 
uv run aeg run --agent my-agent --command "python my_agent.py" --split dev --trials 5
Agent

Storywright

Turns a user story into Playwright API or UI tests and proves they work. It reads the repo, writes the test, runs it against the real app, and repairs what fails. A deterministic guard parses every repair and rejects it for testing less: CI checks it against 30 ways to weaken a test, and 13 real repairs it must allow.

Proves
LLM application development, tool orchestration, and failure handling
Stack
LangGraph, Anthropic SDK (structured outputs, prompt caching), MCP client, Jira Cloud API
Evidence
100% of held-out trials (60/60) vs 53% for a single call on the same model, at $0.0028 per trial. Opus 5.5 went 20/20, one trial per task.
Repository
Write a test from a story file 
cd storywright && uv sync
export ANTHROPIC_API_KEY=...
uv run storywright run --repo ../vendor-intake-app \
  --story story.feature --task-id VEN-01
From Jira, then open the PR (dry run without --yes) 
export JIRA_BASE_URL=... JIRA_EMAIL=... JIRA_TOKEN=...
uv run storywright run --repo ../vendor-intake-app --jira KAN-1
uv run storywright publish --repo ../vendor-intake-app --jira KAN-1 --yes

STORYWRIGHT_PROFILE=report switches from Haiku 5.5 to Opus 5.5.

Agent, Claude Code plugin

agent-dev-skills: review-loop

A pull request reviewer that checks its own work. Every finding must quote real code and survive a second verification pass before it becomes a comment. New commits get a re-review that checks whether old comments were addressed.

Proves
Claude Code skills and plugins, plus precision measured, not assumed
Stack
Claude Code plugin, Python CLI, GitHub Action, Conventional Comments
Evidence
Opus 5.5 names the defect in 29 of 32 seeded bugs (scored by an LLM judge that agrees with blind hand labels at κ = 0.86), with 0 false alarms in 24 harmless changes, 14 of them built to look risky. The same in each of 3 runs.
Repository
Install in Claude Code 
/plugin marketplace add dholman7/agent-dev-skills
/plugin install agent-dev-skills@dholman7-skills
Or run the CLI (prints a review; --post posts it) 
cd agent-dev-skills && uv sync
export ANTHROPIC_API_KEY=... GITHUB_TOKEN=...
uv run review-loop pr --repo owner/name --pr 42
Developer tooling, MCP server

ci-context-mcp

Gives Claude Code, Cursor, or any MCP client the CI context it needs: recent runs, why a run failed, job logs, coverage, and pull request checks from GitHub Actions. Ask "why did CI fail?" and it answers from the real logs.

Proves
MCP server design with a real security model
Stack
MCP Python SDK 2.x, httpx, GitHub REST API
Evidence
Six read-only tools. GET-only client, repo allowlist, and the token never leaves GitHub. Coverage is read from the pytest-cov summary line.
Repository
Add it to Claude Code 
cd ci-context-mcp && uv sync
claude mcp add ci-context \
  -e GITHUB_TOKEN=github_pat_... \
  -e CI_CONTEXT_REPOS=owner/app,owner/lib \
  -- uv run --project "$PWD" ci-context-mcp

Use a fine-grained token with Actions: read and Contents: read on the listed repos only.

One story, start to finish

This happened on October 29, 2026, with story KAN-4: "A rejection note can't be blank." Every step is in the public history.

  1. The story goes into JiraTwo Gherkin scenarios: a whitespace-only note is refused, and a real note is stored without surrounding spaces.
  2. Storywright writes and verifies the testsIt made 4 repo lookups, wrote 2 tests, and both passed against the running app on the first try, for $0.0041.
  3. The tests are checked against real bugsAllowing a blank note made exactly the first test fail. Skipping the trim made exactly the second fail.
  4. Storywright opens the pull requestPR #4 adds one test file, links the story, and moves the issue to In Review. CI ran all 5 checks green.
  5. review-loop reviews itIts comments were checked against the code. Neither held up, so nothing was posted.
  6. Merge closes the storyA workflow commented the merge commit on KAN-4 and moved it to Done. No one touched Jira.

Terms used here

Seeded bug
A small, deliberate defect put into a copy of the app. A good test fails when it is present.
Held-out split
Tasks set aside from prompt tuning and used for scoring. A held-out score is only blind if no earlier result on those tasks shaped the agent; Storywright's current ones aren't.
Confidence interval
The range a success rate likely falls in. When two agents' ranges don't overlap, the difference isn't noise.
Gherkin
Plain-language acceptance criteria written as Given / When / Then. Every task starts from one.
MCP
Model Context Protocol, the standard way to give an AI assistant tools such as "read this CI log".
dev and report profiles
Haiku 5.5 for cheap iteration, Opus 5.5 for any number that gets published or acted on.
Playwright
A browser and API testing framework. All generated tests are Playwright API or UI tests in TypeScript.
Conventional Comments
Review comments that start with a label such as issue or nitpick and say whether they block the merge.
